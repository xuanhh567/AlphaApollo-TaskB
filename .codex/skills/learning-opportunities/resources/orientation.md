# Repo Orientation: AlphaApollo

> Generated by orient. Re-run to update.

## One-line purpose
AlphaApollo 是一个面向大模型深度 agentic reasoning 的 Python 框架，用统一的环境、工具、数据预处理和训练/自进化工作流支持多轮推理、SFT、RL 和 policy-verifier 式改进。

## Primary language(s)
Python 为主。仓库内还嵌入了一个 RAG/DeepWiki 子项目，包含 TypeScript/JavaScript 和额外 Python 依赖，但根项目的主入口、配置和训练逻辑都是 Python。

## Pipeline / workflow stages
1. 读取 YAML 工作流配置，决定要运行哪些预处理模块和哪个训练/推理入口。
2. 预处理脚本从 HuggingFace 或本地 parquet 中抽取题目、答案和元数据，写成统一 parquet schema。
3. verl 或 evolving 入口加载 parquet，并把每条样本的 `env_kwargs` 交给 informal math 环境。
4. 环境管理器构造 prompt、读取/写入 memory，并把模型输出投影成 `<python_code>`、`<local_rag>` 或 `<answer>` 动作。
5. 工具层执行代码、验证或 RAG 检索，环境把 observation/reward/done/info 返回给 rollout 或 self-evolution loop。
6. RL/SFT 路径把轨迹交给 verl trainer；evolving 路径用 policy、verifier、summarizer 和历史解答做多轮自改进。

## Key files
- `README.md` — 说明项目目标、安装、quick-start 和代码结构 | 新人先用它建立“这个系统能做什么”的整体图。
- `alphaapollo/workflows/api.py` — 统一加载 YAML、运行预处理模块、启动 runner，并拆分 `preprocess.*` 覆盖项 | 理解命令行入口实际做了什么。
- `examples/configs/rl_informal_math_tool.yaml` — RL/GRPO 示例配置，串起数据集、verl trainer、环境和工具开关 | 学会从配置追踪一次训练。
- `examples/configs/vllm_informal_math.yaml` — evolving 示例配置，定义 policy/verifier 环境数、模型服务和自进化轮数 | 学会自进化流程需要哪些运行时组件。
- `alphaapollo/data_preprocess/prepare_rl_training_data.py` — 将数学数据集标准化成 prompt、reward_model、extra_info、env_kwargs | 理解下游环境依赖的数据契约。
- `alphaapollo/core/environments/env_manager.py` — 选择训练/自进化环境管理器，拼接 prompt、memory、projection 和 vectorized env | 环境运行时的主枢纽。
- `alphaapollo/core/environments/informal_math_training/env.py` — 单个数学任务环境，解析工具标签、执行工具、判断 done 和 reward | 理解模型每一步如何影响环境。
- `alphaapollo/core/environments/informal_math_training/projection.py` — 将原始模型输出裁剪/校验为一个结构化动作 | 排查 invalid action、多个标签或 answer/tool 冲突时先看这里。
- `alphaapollo/core/tools/manager.py` — `InformalMathToolGroup` 注册 `python_code`、`local_rag` 和 `informalmath_verify` | 扩展或禁用工具的核心位置。
- `alphaapollo/core/generation/evolving/evolving_main.py` — policy-verifier 自进化主循环，处理重复采样、报告聚合、历史解答和结果保存 | 理解 inference-time self-improvement 的主线。

## Core concepts
**配置驱动工作流**: `examples/configs/*.yaml` 描述预处理和 runner，`alphaapollo/workflows/api.py` 负责执行；多数日常实验是改配置和 CLI override，而不是手写新入口。

**统一数据 schema**: 预处理脚本把不同来源数据归一成 `prompt`、`reward_model`、`extra_info`、`env_kwargs` 等字段；环境 reset 主要依赖 `env_kwargs.question` 和 `env_kwargs.ground_truth`。

**环境管理器与多轮交互**: `env_manager.py` 包装 vectorized env、projection、memory 和 prompt 模板；训练路径使用 `InformalMathTrainingEnvironmentManager`，自进化路径使用 `InformalMathEvolvingEnvironmentManager`。

**XML 风格工具动作**: 模型通过 `<python_code>...</python_code>`、`<local_rag>...</local_rag>`、`<answer>...</answer>` 等标签行动；`projection.py` 负责抽取和标记有效性，`env.py` 负责真正执行工具。

**Policy-verifier 自进化**: `evolving_main.py` 让 policy 生成解答、verifier 生成 `<report>` 判断，再把高分或带反馈的历史解答写入 memory，用于后续 round。

## Common gotchas
1. `pyproject.toml`/`setup.py` 的包名仍是 `verl`，并把 `alphaapollo/core/generation` 加到 package root；运行时通常还要让 `PYTHONPATH` 同时包含项目根目录和 `alphaapollo/core/generation`。
2. 环境配置有相近的双层 key：管理器常读 `env.informal_math.*`，底层 training env 默认还读 `env.informal_math_training.*`；改工具开关或 timeout 时要确认两边是否都需要同步。
3. 新工具不是只加一个函数就够了：需要在 `ToolGroup` 注册、在 `TOOL_PATTERNS`/`TOOL_CALLING_TOKENS` 中加入标签、更新 prompt 模板，并确认 projection 的“单动作”有效性规则。

## Suggested exercise sequence
1. 打开 `README.md`，阅读 `Supported features`、`Quick-start recipes` 和 `Code Structure`。读完后合上文件，用 3-4 句话向非开发者解释 AlphaApollo 解决什么问题，以及它的训练、工具和自进化三条能力线分别是什么。
2. 打开 `examples/configs/rl_informal_math_tool.yaml`，只读 `preprocess` 和 `runner` 两个顶层块。读完后画出或口头说明一次 RL 训练从数据下载到 `main_ppo` 启动会经过哪些阶段，并指出哪三个配置项最可能在换模型/换数据集时修改。
