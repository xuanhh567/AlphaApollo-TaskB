# Phase 3 Plan: 结构化 Tool Call、参数校验与 Dispatcher

**Phase:** 3
**Status:** Planned
**Language:** 中文
**Goal:** 支持统一 `<tool_call>{...}</tool_call>` 协议，按 `SkillSpec.parameters` 校验 arguments，并通过通用 dispatcher 执行 skill。

## Requirements Covered

- CALL-01: 模型侧工具调用必须支持统一结构化格式，例如 `<tool_call>{"name":"...","arguments":{...}}</tool_call>`。
- CALL-02: parser 必须能识别无效 JSON、缺少 `name`、缺少 `arguments`、unknown skill 等错误。
- CALL-03: 参数校验必须按 `SKILL.md` schema 检查 required 字段与基础类型。
- CALL-04: 通用 dispatcher 必须通过 registry 路由 skill，不得包含 `if name == "python_code"` 这类具体工具硬编码。
- CALL-05: dispatcher 必须把成功和失败结果都包装为结构化反馈，并最终进入 `<tool_response>`。
- CALL-06: skill 执行异常、超时、stderr 和非零退出码不能导致 rollout 崩溃。

## Locked Decisions From Context

- Phase 3 统一支持 `<tool_call>{...}</tool_call>`。
- 每个 action 先只允许一个完整 `<tool_call>`。
- JSON 最小结构是 `{"name": "...", "arguments": {...}}`。
- 参数校验复用 `SkillSpec.parameters`。
- dispatcher 先作为独立模块测试，不接入 `env.py`。
- 旧 `<python_code>` / `<local_rag>` 标签兼容留到 Phase 4。

## Wave 1: 数据结构设计

### Task 1.1: 设计 `ToolCall`

**建议字段:**

```text
name: str
arguments: dict[str, Any]
raw_text: str | None
```

**理解重点:**

`ToolCall` 是“模型想调用什么”的内部表示，还不是执行结果。

### Task 1.2: 设计 `ToolError`

**建议字段:**

```text
code: str
message: str
tool_name: str | None
field: str | None
details: dict[str, Any]
```

**常见 code:**

```text
missing_tool_call
invalid_tool_call_tag
multiple_tool_calls
invalid_json
invalid_tool_call_payload
missing_tool_name
missing_arguments
invalid_arguments_type
unknown_skill
missing_required_argument
invalid_argument_type
unsupported_entrypoint_type
entrypoint_import_error
tool_execution_error
```

### Task 1.3: 设计 `ToolResult`

**建议字段:**

```text
ok: bool
tool_name: str
text_result: str
score: int | float | None
raw_output: Any
error: ToolError | None
```

**理解重点:**

旧工具常返回：

```python
{"text_result": "...", "score": 1}
```

所以 `ToolResult` 要能容纳这种返回格式。

## Wave 2: Tool Call Parser

### Task 2.1: 新增 `call_parser.py`

**建议文件:**

```text
alphaapollo/core/skills/call_parser.py
```

**建议函数:**

```python
parse_tool_call(text: str) -> ToolCall | ToolError
```

### Task 2.2: 解析 `<tool_call>` 标签

**要求:**

- 没有 `<tool_call>`：返回 `missing_tool_call`。
- 只有开标签或闭标签不完整：返回 `invalid_tool_call_tag`。
- 多个 `<tool_call>`：返回 `multiple_tool_calls`。
- 成功时提取标签中间内容。

**注意:**

暂不解析旧标签：

```text
<python_code>...</python_code>
<local_rag>...</local_rag>
```

这些留到 Phase 4 做兼容桥接。

### Task 2.3: 解析 JSON payload

**要求:**

- JSON 非法：返回 `invalid_json`。
- JSON 不是 object：返回 `invalid_tool_call_payload`。
- 缺少 `name`：返回 `missing_tool_name`。
- `name` 不是非空 string：返回 `invalid_tool_name`。
- 缺少 `arguments`：返回 `missing_arguments`。
- `arguments` 不是 object：返回 `invalid_arguments_type`。

## Wave 3: 参数校验

### Task 3.1: 实现基础类型判断

**建议函数:**

```python
validate_arguments(spec: SkillSpec, arguments: dict[str, Any]) -> tuple[dict[str, Any], list[ToolError]]
```

**基础类型映射:**

| Skill 类型 | Python 类型 |
|---|---|
| `string` | `str` |
| `integer` | `int`，但不能是 `bool` |
| `number` | `int` 或 `float`，但不能是 `bool` |
| `boolean` | `bool` |
| `object` | `dict` |
| `array` | `list` |

### Task 3.2: 检查 required 和 default

**要求:**

- required 参数缺失：返回 `missing_required_argument`。
- 可选参数缺失且有 default：补默认值。
- 可选参数缺失且无 default：保持缺失。
- 参数类型错误：返回 `invalid_argument_type`。

**理解重点:**

参数错误时不执行工具，因为这类错误应该直接回灌给模型，让模型修正调用格式。

## Wave 4: Dispatcher

### Task 4.1: 新增 `dispatcher.py`

**建议文件:**

```text
alphaapollo/core/skills/dispatcher.py
```

**建议函数:**

```python
dispatch_tool_call(call: ToolCall, registry: SkillRegistry) -> ToolResult
```

### Task 4.2: registry 路由

**要求:**

- 用 `registry.get(call.name)` 查找 skill。
- 找不到：返回 `unknown_skill`。
- 不允许写具体工具名分支。

禁止：

```python
if call.name == "python_code":
    ...
```

### Task 4.3: 支持 `python_function` entrypoint

**行为:**

- 读取 `spec.entrypoint.path`。
- 用 `importlib` 导入 `module:function`。
- 用校验后的 arguments 调用函数。

**错误处理:**

- 不支持的 entrypoint：`unsupported_entrypoint_type`
- import 失败：`entrypoint_import_error`
- 函数执行异常：`tool_execution_error`

### Task 4.4: 归一化函数返回

**要求:**

如果函数返回：

```python
{"text_result": "...", "score": 1}
```

就转成：

```text
ToolResult(ok=True, text_result="...", score=1, raw_output=...)
```

如果函数返回普通对象：

```python
{"value": 2}
```

也应该转成可显示的 `text_result`，例如 JSON 字符串。

1. 合法 `<tool_call>` 能解析成 `ToolCall`。
