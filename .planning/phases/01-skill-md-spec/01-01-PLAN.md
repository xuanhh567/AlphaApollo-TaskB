# Phase 1 Plan: SKILL.md 规范与解析器

**Phase:** 1
**Status:** Complete
**Language:** 中文
**Goal:** 设计 skill 目录与 `SKILL.md` frontmatter 规范，实现最小 parser、字段校验和中文编写说明。

## Requirements Covered

- SKILL-01: 每个 skill 必须是一个目录，并包含一个 `SKILL.md`。
- SKILL-02: `SKILL.md` frontmatter 必须至少声明 `name`、`description`、参数 schema、调用入口和 examples。
- SKILL-03: parser 必须能解析 YAML frontmatter，并把合法内容转换为内部 `SkillSpec`。
- SKILL-04: parser 必须在缺字段或格式错误时返回结构化错误，而不是抛出未处理异常。
- SKILL-05: 仓库必须提供中文 `SKILL.md` 编写说明，能指导他人新增 skill。

## Wave 1: 设计确认，不写代码

### Task 1.1: 阅读并理解 `docs/task-b/design.md`

**目的:** 先理解 `SKILL.md` 中每个字段为什么存在。

**检查点:**
- 能说出 `name`、`description`、`parameters`、`entrypoint`、`timeout`、`examples` 的作用。
- 能解释 `entrypoint` 和 `examples` 的区别。
- 能解释为什么 parser 失败时要返回结构化错误。

### Task 1.2: 确认 Phase 1 最小字段集

**建议字段:**

```yaml
name: string
description: string
parameters:
  - name: string
    type: string
    required: boolean
    description: string
    default: optional
entrypoint:
  type: python_function
  path: module.path:function_name
timeout: optional integer
examples:
  - name: optional string
    arguments: object
```

**验收标准:**
- 字段足够覆盖 `python_code` 与 `local_rag`。
- 字段没有过度设计到 MCP 或复杂脚本执行。

## Wave 2: 数据结构设计

### Task 2.1: 设计 `SkillParameter`

**建议字段:**
- `name`
- `type`
- `required`
- `description`
- `default`

**理解重点:**
`SkillParameter` 是给参数校验和 prompt 自动生成用的，不是执行工具本身。

### Task 2.2: 设计 `SkillEntrypoint`

**建议字段:**
- `type`
- `path`

**理解重点:**
Phase 1 只解析 `entrypoint`，Phase 3 才真正执行。

### Task 2.3: 设计 `SkillSpec`

**建议字段:**
- `name`
- `description`
- `parameters`
- `entrypoint`
- `timeout`
- `examples`
- `source_path`

**理解重点:**
`SkillSpec` 是 registry 未来要保存的核心对象。

### Task 2.4: 设计 `SkillLoadResult` 与 `SkillLoadError`

**建议字段:**

```text
SkillLoadResult:
  ok
  spec
  errors

SkillLoadError:
  code
  message
  path
  field
```

**理解重点:**
错误结构化后，CLI、日志、测试和用户提示都可以复用。

## Wave 3: Parser 实现计划

> 本 wave 当前只是实现计划，不代表已经开始写代码。详细说明见 `docs/task-b/design.md` 的 “Parser 实现计划”。

### Task 3.1: 新增 `alphaapollo/core/skills/schema.py`

**内容:**
- 定义数据结构。
- 先使用 dataclass，降低复杂度。
- 建议包含 `SkillParameter`、`SkillEntrypoint`、`SkillExample`、`SkillSpec`、`SkillLoadError`、`SkillLoadResult`。

**为什么这样做:**
loader 读出来的 YAML 是原始 dict；后续 registry、dispatcher、prompt 不应该依赖散乱 dict，而应该依赖稳定的内部数据结构。

### Task 3.2: 新增 `alphaapollo/core/skills/loader.py`

**内容:**
- 读取 `SKILL.md`
- 提取 frontmatter
- YAML 解析
- 字段校验
- 返回 `SkillLoadResult`

**建议主函数:**

```python
load_skill_from_dir(skill_dir) -> SkillLoadResult
load_skill_file(skill_file) -> SkillLoadResult
```

**错误处理要求:**
- 文件不存在：`skill_file_not_found`
- 缺 frontmatter：`missing_frontmatter`
- YAML 错误：`invalid_yaml`
- 缺字段：`missing_required_field`
- 类型错误：`invalid_field_type`
- 值错误：`invalid_field_value`

### Task 3.3: 新增最小验证样例

**内容:**
- 合法 `python_code` 样例
- 缺少 `name` 样例
- `parameters` 类型错误样例
- `entrypoint.path` 格式错误样例
- `examples` 缺少 `arguments` 样例

**暂定测试目标:**
- 合法输入返回 `ok=True`
- 非法输入返回 `ok=False`
- 测试断言优先使用 error `code` 和 `field`，不要依赖完整 message 文本
