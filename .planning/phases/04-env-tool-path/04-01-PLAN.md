# Phase 4 Plan: 迁移 Env Tool 执行路径与内置 Skill

**Phase:** 4
**Status:** Planned
**Language:** 中文
**Goal:** 把 structured `<tool_call>` 和 Skill dispatcher 接入 `informal_math_training` 环境，同时保留旧 `<python_code>` / `<local_rag>` 标签行为，避免训练路径突然回归。

## Requirements Covered

- COMPAT-01: 新 `<tool_call>` 路径必须能执行 `python_code`。
- COMPAT-02: 新 `<tool_call>` 路径必须能路由 `local_rag`。
- COMPAT-03: 旧 `<python_code>` / `<local_rag>` 标签在过渡期不能被破坏。
- COMPAT-04: 成功、失败、参数错误、工具禁用等情况都要通过 `<tool_response>` 返回给模型，而不是让 rollout 崩溃。

## Locked Decisions From Context

- Phase 4 主目标先接 `informal_math_training`，因为当前 Task B 配置主线是 `env.env_name=informal_math_training`。
- `informal_math_evolving` 先记录差异，除非实现时能低风险复用同一个 helper，否则不同时大改。
- 旧标签继续支持：`<python_code>`、`<local_rag>`、`<informalmath_verify>`。
- 旧标签可以先转成统一内部调用对象，再走新路径。
- `python_code` / `local_rag` 不能直接裸调底层函数；必须保持旧 `InformalMathToolGroup` 的 `text_result` + `score` 语义。
- dispatcher 保持通用，不塞入 env 的 `question`、`ground_truth`、`data_source`。

## Beginner Mental Model

这一阶段可以这样理解：

```text
Phase 3 结束时：
  dispatcher 已经知道“怎么按工具名找工具并执行”

Phase 4 要做：
  让 env.py 在真实训练交互里用上 dispatcher
```

也就是：

```text
模型输出
  |
  v
env.py 判断是不是工具调用
  |
  v
parser / 旧标签桥接
  |
  v
dispatcher 执行 skill
  |
  v
env.py 包成 <tool_response>
  |
  v
返回给模型继续推理
```

## Wave 1: 明确当前旧路径

### Task 1.1: 对照旧 `python_code` 行为

**文件：**

```text
alphaapollo/core/environments/informal_math_training/env.py
alphaapollo/core/tools/manager.py
```

**要确认：**

- `python_code` 禁用时返回什么。
- 空代码时返回什么。
- 执行成功时 `text_result` 和 `score` 是什么。
- 执行失败 / timeout / stderr 时 `text_result` 和 `score` 是什么。
- 当 python 执行失败且 local_rag 启用时，training env 会追加 RAG 提示语。

**为什么：**

新路径必须尽量保留这些行为，否则模型看到的反馈会变，RL 训练结果也可能变。

### Task 1.2: 对照旧 `local_rag` 行为

**要确认：**

- local RAG 禁用时返回什么。
- `repo_name` / `query` 缺失时返回什么。
- RAG 调用成功时返回什么。
- RAG 调用失败时返回什么。
- 旧标签里 JSON 非法时，env 现在如何返回错误。

## Wave 2: 准备 skill entrypoint 兼容层

### Task 2.1: 设计 wrapper 位置

**优先方案：**

```text
alphaapollo/core/skills/builtin/runtime.py
```

**建议函数：**

```python
execute_python_code_skill(code: str, **context) -> dict
execute_local_rag_skill(repo_name: str, query: str, top_k: int = 3, **context) -> dict
```

**注意：**

如果 dispatcher 当前只支持普通 keyword arguments，那么不要急着把 env 状态塞进 dispatcher。

更稳的第一版是：

```text
env.py 使用自己的 InformalMathToolGroup 执行真实工具；
dispatcher 仍负责结构化解析和参数校验；
具体 env context 由 env bridge 处理。
```

### Task 2.2: 判断是否需要 env-side bridge

**建议新增小 helper：**

```text
alphaapollo/core/environments/informal_math_training/skill_bridge.py
```

**可能职责：**

- 把旧 `<python_code>` 转成 `ToolCall(name="python_code", arguments={"code": ...})`。
- 把旧 `<local_rag>` JSON 转成 `ToolCall(name="local_rag", arguments={...})`。
- 调用 `validate_arguments(...)` 复用 schema 校验。
- 用当前 env 的 `self.tool_group` 执行工具，保持旧返回语义。
- 把 dict 输出包装成 `<tool_response>`。

**理解重点：**

dispatcher 是“通用执行器”；env bridge 是“把通用工具系统接进这个具体环境”。

## Wave 3: 在 env 初始化时加载 enabled skills

### Task 3.1: 在 `__init__` 中解析启用 skill

**文件：**

```text
alphaapollo/core/environments/informal_math_training/env.py
```

**使用：**

```python
resolve_enabled_skill_names(env_config)
load_skill_registry_from_dirs(get_builtin_skill_dirs(), enabled_skills=...)
```

**规则：**

- 如果 `env.skills` 存在，优先用它。
- 如果 `env.skills` 不存在，从旧配置推导：
  - `enable_python_code=True` -> `python_code`
  - `enable_local_rag=True` -> `local_rag`
- enabled skill 不存在时，要尽早给清晰错误。

### Task 3.2: 保留旧 tool group 初始化

**要求：**

不要删掉：

```python
self.tool_group = InformalMathToolGroup(...)
self.init_tool_groups([self.tool_group])
```

**原因：**

旧 `InformalMathToolGroup` 仍然保存了真实工具行为、RAG 配置、ground truth、timeout 等环境状态。

## Wave 4: 支持新 `<tool_call>`

### Task 4.1: 扩展 `_parse_action`

**目标：**

`_parse_action(...)` 既能识别旧标签，也能识别新：

```xml
<tool_call>
{"name":"python_code","arguments":{"code":"print(1 + 1)"}}
</tool_call>
```

**建议：**

- 先调用 `parse_tool_call(raw_action)`。
- 如果找到了合法 `<tool_call>`，返回统一内部对象。
- 如果没有 `<tool_call>`，再走旧标签解析。
- 如果 `<tool_call>` 存在但 JSON 错误，要返回一个可进入 `<tool_response>` 的错误，而不是当作普通答案 done。

### Task 4.2: 限制单次 structured tool call

**规则：**

Phase 3 parser 已经规定一个 action 最多一个 `<tool_call>`。

如果模型输出多个 `<tool_call>`：

```text
返回 multiple_tool_calls 错误给模型
done=False
让模型下一轮修正
```

## Wave 5: 执行工具并包装响应

### Task 5.1: 新增统一执行入口

**建议方法：**

```python
def _execute_skill_tool_call(self, call: ToolCall) -> tuple[str, dict]:
    ...
```

**返回：**

```text
observation: "\n<tool_response>...</tool_response>\n"
tool_info: metadata dict
```

### Task 5.2: 保留旧 metadata 形状

**metadata 至少继续包含：**

```text
tool_calling
tool_group
tool_name
tool_input
data_source
```

**新增 structured 路径可额外包含：**

```text
tool_call_format: "structured" | "legacy"
error
score
```

### Task 5.3: 参数错误也返回 `<tool_response>`

例如模型输出：

```json
{"name":"python_code","arguments":{}}
```

应该返回类似：

```xml
<tool_response>{"status":"error","error":"missing_required_argument","message":"..."}</tool_response>
```

不要继续执行工具。

## Wave 6: 保留旧标签兼容

### Task 6.1: 旧 `<python_code>` 转统一调用

旧：

```xml
<python_code>print(1 + 1)</python_code>
```

内部转成：

```python
ToolCall(name="python_code", arguments={"code": "print(1 + 1)"})
```

### Task 6.2: 旧 `<local_rag>` 转统一调用

旧：

```xml
<local_rag>{"repo_name":"sympy","query":"solve equations","top_k":3}</local_rag>
```

内部转成：

```python
ToolCall(
    name="local_rag",
    arguments={"repo_name": "sympy", "query": "solve equations", "top_k": 3},
)
```

如果 JSON 非法，保留旧错误语义：

```xml
<tool_response>Error: Invalid JSON input for local_rag</tool_response>
```

### Task 6.3: 旧 `<informalmath_verify>` 暂时保留原路径

**原因：**

Task B 当前主线要求是 `python_code` / `local_rag` skill 化。`informalmath_verify` 可以后续再独立迁移，避免本阶段范围变大。
