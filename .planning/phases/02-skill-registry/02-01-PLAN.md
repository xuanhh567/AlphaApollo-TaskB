# Phase 2 Plan: Skill Loader、Registry 与启用配置

**Phase:** 2
**Status:** Planned
**Language:** 中文
**Goal:** 扫描 skill 目录，注册合法 skill，并通过声明式配置决定启用哪些 skill，同时兼容旧的工具开关。

## Requirements Covered

- REG-01: Skill loader 必须能扫描配置指定的 skill 目录。
- REG-02: Registry 必须能按 `name` 注册和查找 skill。
- REG-03: 重名 skill 必须返回清晰错误或拒绝注册，不能静默覆盖。
- REG-04: 启用工具应由声明式配置控制，例如 `env.skills=[python_code, local_rag]`。
- REG-05: 初期必须兼容旧的 `enable_python_code` 与 `enable_local_rag` 配置，降低回归风险。

## Locked Decisions From Context

- Phase 2 做 `Registry + 配置`，不提前接入 `env.py`。
- 扫描多个 skill 时采用“收集错误继续”的策略。
- Phase 2 现在创建 `python_code` / `local_rag` 的 `SKILL.md`，但暂时不执行。
- 如果 `env.skills` 存在，优先使用新配置；否则从旧配置推导。

## Wave 1: Registry 数据结构设计

### Task 1.1: 设计 registry 返回结果

**建议新增:**

```text
SkillRegistryError
SkillRegistryLoadResult
```

**建议字段:**

```text
SkillRegistryError:
  code
  message
  path
  skill_name

SkillRegistryLoadResult:
  registry
  loaded
  errors
```

**理解重点:**

loader 的错误是“某一本 `SKILL.md` 写错了”；registry 的错误是“工具目录整体注册时出问题了”，比如重名、配置启用了不存在的 skill。

### Task 1.2: 设计 `SkillRegistry`

**建议能力:**

```python
register(spec) -> list[SkillRegistryError]
get(name) -> SkillSpec | None
require(name) -> SkillSpec
names() -> list[str]
specs() -> list[SkillSpec]
```

**理解重点:**

registry 内部保存的是：

```text
dict[str, SkillSpec]
```

不要保存原始 YAML dict。原因是 Phase 1 已经把 YAML 转成了稳定的 `SkillSpec` 内部契约。

## Wave 2: 扫描和注册

### Task 2.1: 实现 `register(spec)`

**要求:**

- 如果 `spec.name` 不存在，注册成功。
- 如果 `spec.name` 已存在，返回 `duplicate_skill` 错误。
- 不静默覆盖旧 skill。

**测试:**

- 注册一个 skill 后，`get(name)` 能取回同一个 `SkillSpec`。
- 注册两个同名 skill 时返回 `duplicate_skill`。

### Task 2.2: 实现 `load_skill_registry_from_dirs(...)`

**建议函数:**

```python
load_skill_registry_from_dirs(skill_dirs, enabled_skills=None) -> SkillRegistryLoadResult
```

**行为:**

- 对每个目录调用 Phase 1 的 `load_skill_from_dir(...)`。
- 合法 skill 注册进 registry。
- 非法 skill 的 loader errors 被转换或收集到 registry result。
- 如果某个 skill 不在 `enabled_skills` 中，可以跳过注册。

**理解重点:**

registry 不重新解析 YAML。它只负责组织 Phase 1 loader 的结果。

### Task 2.3: 实现内置 skill 目录发现

**建议新增:**

```python
get_builtin_skill_dirs() -> list[Path]
```

**扫描位置:**

```text
alphaapollo/core/skills/builtin/*/SKILL.md
```

**要求:**

- 只返回包含 `SKILL.md` 的一级目录。
- 返回顺序稳定，方便测试。

## Wave 3: 内置 SKILL.md

### Task 3.1: 创建 `python_code/SKILL.md`

**路径:**

```text
alphaapollo/core/skills/builtin/python_code/SKILL.md
```

**字段重点:**

- `name: python_code`
- `parameters` 至少包含 `code`
- `timeout` 建议 30
- `entrypoint` 暂时写未来可执行的 Python function path

**注意:**

Phase 2 只加载元数据，不执行 entrypoint。

### Task 3.2: 创建 `local_rag/SKILL.md`

**路径:**

```text
alphaapollo/core/skills/builtin/local_rag/SKILL.md
```

**字段重点:**

- `name: local_rag`
- `parameters` 包含 `repo_name`、`query`、`top_k`
- `top_k` 可选，默认 3
- `timeout` 建议 60

**注意:**

参数命名应贴近当前 `InformalMathToolGroup.local_rag(repo_name, query, top_k=3)`。

## Wave 4: 启用配置与旧配置兼容

### Task 4.1: 设计 enabled skills 解析函数

**建议函数:**

```python
resolve_enabled_skill_names(config, env_section="informal_math") -> list[str]
```

**规则:**

1. 如果存在 `env.skills`，直接使用它。
2. 如果不存在 `env.skills`，从旧配置推导：
   - `enable_python_code=true` -> `python_code`
   - `enable_local_rag=true` -> `local_rag`
3. 返回顺序保持稳定。

**理解重点:**

这一步只是把配置转成 skill name 列表，不执行工具。

### Task 4.2: 处理配置启用了不存在的 skill

**要求:**

如果 `enabled_skills=["python_code", "missing_tool"]`，而扫描结果里没有 `missing_tool`，应返回：

```text
unknown_enabled_skill
```

**不要:**

- 不要静默忽略。
- 不要等到 dispatcher 执行时才报错。
